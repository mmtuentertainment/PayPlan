### 2. PayPlan's 4 Enhancements Over Vanilla Spec-Kit

**1. Bot Review Loop**:
- Claude Code Bot + CodeRabbit AI review all PRs
- Categorize feedback (CRITICAL/HIGH/MEDIUM/LOW)
- Fix CRITICAL + HIGH immediately
- Defer MEDIUM + LOW to Linear (prevents review loops)
- Iterate until both bots ✅ GREEN
- **Impact**: 100% of CRITICAL issues caught before merge

**2. Phased Constitutional Principles**:
- Quality evolves with user count (Phase 1-4)
- Coverage ramps 60%→70%→80%→90% (sustainable)
- TDD adoption phased (test-after → hybrid → strict)
- **Impact**: Achieves 85%+ coverage by Week 12 without burnout

**3. Implementation Prompts**:
- Manus creates `.claude/prompts/implement-[feature].md`
- Contains spec summary, key constraints, critical patterns
- Explicit bot review expectations
- **Impact**: Clearer handoff from Manus to Claude Code

**4. Feature-Based Architecture**:
- Mandated `features/*/lib/` structure
- Business logic clearly separated (easier TDD enforcement)
- Barrel exports (`index.ts`) for clean imports
- **Impact**: Self-contained features, easier testing

### 3. Anti-Patterns from Real Mistakes

**10 anti-patterns extracted from PayPlan production**:
1. Implementation details in spec (locks tech stack)
2. Skipping clarification (50% rework cost)
3. Constitutional violations (bot auto-rejects)
4. All tasks in one phase (no parallelization)
5. Vague success criteria (can't validate)
6. Too many clarifications (>3 markers)
7. Ignoring bot feedback (quality issues slip)
8. Missing parallel markers (loses concurrency)
9. Tests after-the-fact (Week 7+ violation)
10. Ignoring foundational dependencies (blocks implementation)

**Each includes**: Bad example, Good example, Impact, Recovery strategy
